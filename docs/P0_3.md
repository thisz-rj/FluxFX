# P0.3 — staggered MAC velocity

Implemented in release **0.3.0**, building on Git baseline `20cf95b`.
The UI now runs `DenseMACAdvection`; the previous `DenseAdvection` class and
its test suite remain available as the P0.2 regression baseline.

## Layout and units

Each component has front/back R32F textures:

| Component | Shape | Sample position in cell units |
| --- | --- | --- |
| U | (Nx+1, Ny, Nz) | (i, j+0.5, k+0.5) |
| V | (Nx, Ny+1, Nz) | (i+0.5, j, k+0.5) |
| W | (Nx, Ny, Nz+1) | (i+0.5, j+0.5, k) |
| Density | (Nx, Ny, Nz) | (i+0.5, j+0.5, k+0.5) |

Physical position multiplies these coordinates by `extent / cell_count`.
Velocity is metres/second; the UI defaults to a one-metre cube. Non-cubic grids
and unequal physical extents are covered by tests. At 128³, one face dimension
is 129; the cell-resolution limit remains 128, without truncating boundary faces.
Signed velocity uploads are supported; density uploads still reject negative values.

## Step contract

1. Gather all three staggered components with trilinear interpolation to reconstruct
   velocity at an arbitrary physical position.
2. At each U face, backtrace with the midpoint rule through the old U/V/W fields,
   then write the sampled old U value to the new U texture.
3. Do the same for V and W, still reading the exact same old three fields.
4. Advect density through the new velocity, then apply density decay and injection.
5. Swap all velocity and density references after the four dispatches succeed.

Reset seeds face velocities from the initial translation/rotation controls and
seeds the spherical density source. `reset(seed=False)` empties density but still
reinitializes velocity. Velocity is subsequently advected, not re-seeded each step.
No CPU voxel loops or per-frame CPU readbacks are introduced.

Velocity uses constant extension outside the stored face grid. Density still has
zero extension. There are no solid-wall boundary conditions, projection, velocity
source forcing, buoyancy, or adaptive substeps. Self-advection can generate
divergence; a divergence-free initial field is not guaranteed to remain so until
P0.5. The current view remains a 2D density slice.

## Validation on Apple M5 Pro / Metal

Blender 5.3.0 Alpha, build `b2e052b7172a`, 2026-09-20.

- 24 standalone tests pass, including 8 new MAC invariants: dimensions/memory,
  face locations, signed constant flow, affine reconstruction, stationary shear,
  exact density translation driven by stored velocity, zero fields, and extrema.
- Four GPU/CPU comparisons pass on a 7×5×3 grid with unequal physical extents:
  zero velocity, constant flow, shear, and signed spatially varying flow. Each
  uses four consecutive complete steps without intermediate readback.
- Maximum velocity error: **1.369e-6**. Maximum density error: **2.138e-6**.
  Tolerance: 2e-5. Seed values match the analytic initializer within 4e-8.
- Reset reproduces all initial face fields exactly on the tested small grid.
- 64³ and 128³ complete 30 steps with finite density and signed velocity; density
  remains nonnegative. Eight fields use **8,486,912 bytes** and **67,502,080 bytes**
  respectively (excluding GPU resource overhead).
- P0.2 GPU regression and nine runtime/lifecycle checks pass with the new backend.
  Undo/file-load cleanup hooks are invoked directly, not by altering user files.

Evidence: [MAC GPU report](validation/m5-pro-mac-p03.json),
[baseline regression](validation/m5-pro-baseline-p03.json), and
[lifecycle report](validation/m5-pro-ui-p03.json).

These are correctness smoke tests, not GPU timing or production-quality claims.
The next stage is **P0.4: temperature and buoyancy**, followed by pressure projection
and a measured divergence-reduction acceptance gate in P0.5.
