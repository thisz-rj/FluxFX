# P0.8 — adaptive timestep estimates

Tested September 21, 2026, Blender 5.3.0 Alpha b2e052b7172a, Apple M5 Pro / Metal.
Adaptive mode is on by default, with maximum dt 1/30 s and target CFL 0.75.

## Behaviour

Before a step, hierarchical GPU passes reduce the maximum absolute value of U,
V, W, density, and temperature. Each pass reduces a 4×4×4 tile, bounds-checking
odd dimensions. Only the final five scalar floats return to Python. No voxel
loops or full simulation-field transfers run in the playback path.

With component maxima M and cell spacing h, the transport rate bound is
`r = Mu/hx + Mv/hy + Mw/hz`. The buoyancy bound is
`a = (heat_lift * max_abs_temperature + density_weight * max_abs_density) / hz`.
The selector halves the maximum dt until `r*dt + a*dt² <= target`.

Quantizing dt in powers of two reduces frequent pressure warm-start invalidation.
A changed dt triggers the existing cold pressure solve. No accumulated frame-time
budget is consumed: one timer callback advances one chosen step, so fast flow
can run slower in simulation time. This is an accuracy-oriented estimate for
semi-Lagrangian transport, not a proof of fluid stability or incompressibility.
Pressure correction can increase local component speeds; this estimate does
not bound that increase or retry/roll back the resulting step.

NaN/Inf values propagate a large sentinel through the reduction and stop the
step. Extremely large fields or a required dt below 1 microsecond also stop with
an error, rather than silently violating the target. Fixed mode is available for
comparison and does not perform reduction readback or these adaptive checks.

## UI and ownership

Toggle **Adaptive timestep** and edit **CFL target** without rebuilding smoke.
The existing setup panel exposes the maximum timestep. The sidebar reports the
last successfully completed dt and estimated CFL. Step wall time includes the
synchronous reduction reads, but not necessarily completed simulation GPU work
or rendering; it must not be interpreted as GPU frame time.

`physics/timestep.py` contains the pure selection rule; `backend/timestep.py`
owns reduction shaders and scratch textures. The Blender runtime applies the
selected dt to the existing solver. Cleanup releases the controller. Reduction
scratch adds 86,508 bytes at 64³ and 678,884 bytes at 128³ (allocated even in fixed
mode). Total field storage is approximately 18.239 / 145.272 MiB.

## Validation

53 standalone tests pass, including rest, fast flow, acceleration from rest,
combined bounds, invalid inputs, and the minimum-step stop. Metal GPU checks:

- Non-cubic 9×7×5 signed fields match CPU maxima within 2e-6.
- NaN field detection stops selection.
- A 64³ heated-flow run completed 90 adaptive steps, reducing dt from 1/30 to
  1/60 s and advancing 1.9 simulated seconds.
- A 128³ run completed 20 adaptive steps, also reducing to 1/60 s and advancing
  0.516667 simulated seconds.

Every selected estimate stayed within the 0.75 target. Last sampled pressure
RMS ratios were 0.0190 at 64³ and 0.0509 at 128³. These are specific validation
runs, not general convergence or performance guarantees. All 13 UI/lifecycle
checks pass, including adaptive reporting and reduction-resource cleanup.

## Remaining work

Five scalar readbacks introduce synchronization cost. A native GPU-driven
controller could remove that stall later. Projection-aware retry, frame-budget
substepping, better pressure solvers, and general scene integration remain out
of scope. Next is P0.9: measured performance benchmarks and bottleneck reporting.
